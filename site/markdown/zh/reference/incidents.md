# 事件证据

规则识别候选观察，不直接确认客户端缺陷。HTTP 失败、配置的业务拒绝、预期取消和证据缺失分别处理。

## 证据窗口

单个事件最多保存前 30 秒的 120 个引用和后 10 秒的 80 个引用，总计最多 200。以宿主收到时间为准，设备时钟不能延长窗口。同指纹只在原期限内合并；窗口关闭只触发一次就绪，即使后续没有新事件。

每项目最多 100 个事件、实例最多 400 个。清除、撤销、到期与代次变化会移除派生记录并失效回调，不写磁盘事件快照。

## 完整性与含义

延迟依据 response 或 complete 中有限 duration/elapsed，首字节时间不代表总延迟。无 code 错误仅产生通用网络失败，不从自由文本猜因；未知 code 不分类。取消属于信息，不作为自动缺陷证据。

缺口包括窗口截断、序号缺失、采集上限、证据不可用与事件上限。已知构建映射只是来源信息，不能证明源码内容或行号；缺失和歧义保持显式。

列表与详情绑定项目代次，默认 50 条、最多 200 条且字节有界。默认摘要，正文每次读取都需当前许可。翻页见 [MCP](mcp.md)，编排见[诊断生命周期](diagnosis.md)。
